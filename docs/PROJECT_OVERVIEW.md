# KeyPilot：制作动机、功能与演进

[项目首页](../README.md) · [安装运行](START_HERE.md) · [逐版本记录](VERSION_HISTORY.md) · [历史来源](HISTORY_SOURCES.md)

KeyPilot 是从 Copilot 按键自定义工具逐步发展而来的 Windows 桌面语音助手。它把常用电脑操作做成明确的 Skill，用规则处理直接命令，用可替换的本地模型补充语言理解，再按需接入问答、外部助手和语音合成。

## 制作动机

最初的问题很具体：电脑带有 Copilot 键，但系统提供的自定义方式不能满足使用需求。2026 年 9 月 2 日的开发目标分成两步：先让这个按键打开指定应用、快速进入语音；再让它成为类似系统内置助手的入口，能直接控制电脑的基础功能。

实际使用随后提出了更多要求。打开应用、调音量、调亮度，不应依赖一次复杂的云端推理；简单语音操作也不应不断创建新的聊天记录。本地模型需要的是明确的可用操作和参数约束，遇到能力之外的问题再转接。响应速度、资源占用和日常可用性，成为架构选择的主要依据。

声音功能也是从使用反馈逐步发展出来的：先解决能否朗读，再改善音色、开口等待、长回答的连续播放和中英文表现。最后，项目需要能够在另一台电脑上安装、更换模型并导入自备音色，因此加入了固定依赖、统一入口、接入 Skill 和公开的语音包规范。以上动机来自开发任务的初始需求及后续反馈，依据见 [H01–H03](HISTORY_SOURCES.md#证据索引)。

## 当前功能

下表描述当前公开源码中的能力。涉及外部模型、Windows 服务或声音资源时，需要先完成相应配置。

| 功能 | 使用方式或示例 | 使用条件 |
| --- | --- | --- |
| 打开应用与本机内容 | “打开计算器”；匹配开始菜单、桌面项目及有限层级子目录，或已配置的文件/文件夹关键词 | 目标必须已安装或存在；支持名称匹配，不负责下载应用 |
| 音量与亮度 | “音量调到百分之三十”“屏幕调亮一点”；查询、增减、静音 | 亮度取决于显示设备接口；不支持时打开显示设置 |
| 系统设置 | “打开蓝牙设置”“在设置里找颜色管理” | 能定位的页面直接打开，其他查询尝试填写搜索框；不代表所有设置都能自动修改 |
| 网站与关键词 | 打开常见网站、HTTP/HTTPS 地址或搜索；在设置中维护网站和应用/文件两类关键词 | 本机路径可直接打开；网站和搜索需要网络 |
| 天气与世界时间 | “芝加哥今天天气怎么样”“伦敦现在几点” | 天气使用联网服务；世界时间使用预设城市和时区数据 |
| 时钟助手 | 倒计时、闹钟、提醒、世界时间四个页面；查看/取消任务，选择和试听铃声 | 任务保存在本机；到点通知需要后台计时进程，详见下文 |
| 日历草稿 | 通过提醒操作生成日历事件 | 生成 `.ics` 并打开关联应用，最终导入由使用者确认 |
| 本地模型理解 | 规则未命中的操作交给模型选择 Skill 和参数；也可进行本地问答 | 先连接模型服务；模型输出经过白名单和参数校验 |
| 网页读取与联网问答 | 读取当前浏览器页面、Google AI 答案，或使用外部问答服务 | 依赖相应浏览器、模型或服务；网页读取是文本读取，不是截图理解 |
| 输入与上下文 | 文字输入、Windows 听写；保留当天有限的最近对话，支持清除上下文 | 默认最多保留最近 4 轮；听写使用 Windows `Win+H`，并非自带离线识别模型 |
| 结果与朗读 | 最后结果可编辑、复制和重新朗读；设置中可朗读剪贴板；开始听写可打断播报 | 自动语音回复默认关闭；手动朗读和试听仍可使用当前选择的可用声音 |
| 声音与资源调度 | 系统声音、联网声音、自定义本地语音包；按需加载或预热常驻 | 自定义声音需另备资源；不同引擎的硬件与网络要求不同 |
| 按键与门户 | 启动按键监听后，单击唤起/最小化，双击开始/取消听写；可配置子应用入口 | 默认模板提供本地助手，不自动接管按键或安装开机任务 |
| 模型和语音扩展 | 发现模型、只读测试、导出操作契约；导入、刷新、选择和试听本地声音 | 标准语音包导入目前支持 ZipVoice；模型服务支持 Ollama 与 OpenAI 兼容协议 |

当前注册了 12 个运行时 Skill，其中 11 个提供给本地模型；`codex_fallback` 属于应用侧的可选后备能力。模型可以提出操作，实际执行仍由应用完成。全部协议和调用边界见 [本地模型门户](LOCAL_MODELS.md) 与 [架构说明](ARCHITECTURE.md)。

### 问答与复杂操作分别设置

设置中的知识问答等级决定问题交给谁回答，电脑操作仍优先走本地 Skill。

| 等级 | 回答方式 |
| --- | --- |
| 0：关闭 | 关闭自动联网问答；已配置本地模型时仍可本地回答 |
| 1：需要时 | 尝试本地回答，需要时搜索并读取网页 |
| 2：Google AI | 读取 Google AI 页面答案；失败会提示，不用本地模型另写一个答案冒充网页结果 |
| 3：Marvis | 把问题转接给已安装的 Marvis 客户端；当前不自动取回完整回答 |
| 4：云端 API | 通过配置的兼容 API 获取回答，支持选择模型与连接测试 |

复杂操作另有 `关闭 / Codex / Marvis` 选项；部分本地问答还可在征得同意后转交 ChatGPT 客户端。这些转接需要相应软件与账户。KeyPilot 的模型契约没有开放任意终端命令或通用多步骤电脑控制。

0 级也不等于禁止所有网络：明确打开网站、查询天气，以及选择联网声音，仍可能访问各自的服务。

### 声音设置的三个维度

- **回复长度与语速**：低/中/高三档上限约为 120/600/6000 字；语速在 0.90×–1.10× 范围内微调。结果重读和剪贴板朗读沿用当前设置。
- **调度方式**：性能模式按需加载、空闲释放；质量模式预热并常驻，减少反复加载。常驻会持续占用资源。
- **生成精度与模型选择**：ZipVoice 提供 4/8/16 步等生成精度选项。历史本机包还使用过快速/高质量及按语言选择模型的配置，这些依赖具体包内资源，并非空模板自带的音色。

CPU ZipVoice 播报前会按中文上下文处理数字、日期、时间和百分比，保留部分型号表达。其他引擎各自的文本处理方式不完全相同。

### 时钟与按键后台

仅运行 `gui` 可以打开界面并创建任务，但不会启动负责到点提醒的后台进程。当前统一入口中，运行以下命令会启动按键监听和独立的计时进程：

```powershell
.\.venv\Scripts\python.exe scripts/keypilot.py hook
```

该命令会接管配置的按键；只需基础文字功能时不必运行。复现版不会自动注册开机任务，所以不能把任务文件的持久保存理解为重启电脑后一定会自动响铃。退出与后台进程说明见 [项目入口](START_HERE.md#4-数据位置与退出)。

## 从最初需求到当前版本

下面按“遇到什么问题、增加了什么功能”说明演进。应用版本和语音实验编号分别记录；日期按历史记录的 UTC 时间归日。完整补丁、失败试验及来源见 [版本迭代历史](VERSION_HISTORY.md)。

### 1. 先把 Copilot 键变成可自定义入口

**2026-09-02–03，v0.1.0–v0.1.5。** 第一版支持通过单击、双击和长按启动应用或快捷键。实际测试发现目标键盘长按会表现为 Ctrl、旧进程未重载配置、退出宿主后后台失效，以及应用冷启动时语音快捷键发得太早。

这一阶段依次加入配置重载、同一窗口最小化/恢复、独立登录任务和等待窗口就绪后触发语音。项目由一个按键映射脚本，变成了能够独立运行的入口程序。

### 2. 做成能处理基础操作的独立助手

**2026-09-03，v0.2.0–v0.4.0。** 为了让简单操作直接完成，加入独立 GUI、文字输入和 Windows 听写，落实打开应用、调音量、调亮度、打开设置及设置搜索等 Skill。

随后加入系统/联网声音、试听与低风险语音自动提交，并修正不同离线声音实际回退为同一音色的问题。最终合并为一个桌面入口：后台处理按键，界面处理对话与操作，关闭界面后仍可再次唤起。历史安装版启用了登录常驻；公开复现版把它改为主动选择。

### 3. 让本地模型补充语言理解

**2026-09-03，v0.5.0–v0.8.1。** 固定关键词无法覆盖所有说法，于是接入 Ollama 的 Qwen 模型：规则先尝试，未命中再由模型选择 Skill 和参数，程序负责验证与执行。类似“声音别太大，放一半”因此可以转为明确的音量操作。

这一阶段还加入普通问答、天气 Skill 和是否转交 GPT 的交互；完善请求复制、转接失败保留内容，以及按天复用外部会话状态。按键手势收敛为单击唤起/最小化、双击听写，减少简单命令产生额外聊天的需要。

### 4. 从基础控制扩展到日常桌面使用

**2026-09-03，v0.9.0–v0.14.0。** 按实际使用问题扩展网站打开与搜索、可视化时钟、倒计时/闹钟/提醒、循环铃声，以及当前网页读取。

为改善交互，增加大结果区、复制、有限上下文和清除按钮；把播放放入可终止进程，让开始听写和新回复能够停止旧播报。设置搜索增加窗口等待、搜索框填写和回读，修复连续第二次搜索失效。

应用查找扩展到桌面项目、名称近似匹配和模型辅助别名，并加入网站关键词、应用/文件关键词及路径编辑。使用者可以把自己常用的网址和资料入口交给助手管理。

### 5. 明确知识答案来源，并降低空闲占用

**2026-09-03，v0.15.0–v0.18.0。** 本地模型回答知识问题时可能不可靠，因此加入问答强度选择和 Google AI 搜索读取。搜索使用无痕窗口；用于应用别名查找的临时窗口可自动关闭，普通搜索窗口保留。

在多次反馈后，Google AI 档改为直接提取页面答案，本地模型只参与操作路由；页面失败时明确报错。随后统一语音提交与手动执行的路由，避免某条路径提前使用本地答案。模型改为按需加载和空闲卸载，减少长期后台占用。

### 6. 将问答服务与复杂操作代理分开

**2026-09-03，v0.19.0–v0.20.1。** 增加兼容 API 地址、密钥加密保存、模型选择和连接测试；接入 Marvis 客户端转接。知识问答形成 0–4 档，复杂操作则独立选择 Codex、Marvis 或关闭。

随着设置增多，主界面重新精简为对话与结果区，把模型、声音、联网等级和关键词管理放入设置弹窗。9 月 4 日，历史应用源码先归档到私有远端。

### 7. 增加独立音色，并完善朗读控制

**2026-09-07–08，v0.21 系列至 v0.22.0。** 在普通声音之外加入独立自定义音色选择，先探索参考录音直接合成，再尝试“固定基础朗读 + 本地 RVC 变声”，保留原路线供比较。

声音反馈推动了参考音清理、响度与峰值处理，以及自然语速调整。为解决短回答被截断和长回答过长，加入低/中/高朗读长度、0.90×–1.10× 语速微调和剪贴板朗读。Google 页面读取也继续修正正文定位与短答案提取。

### 8. 优化生成等待，探索 CPU 路线

**2026-09-08，v0.23.0 及后续修复。** 单纯调整音高和语速无法解决开口慢，于是加入性能/质量调度：按需加载与空闲释放，或者预热常驻；播放当前段时预先生成下一段。随后修复 RVC 预热卡住，并改善分段生成与连续播放。

为了减少独显占用，又探索 ZipVoice ONNX INT8 的 CPU 推理。零样本试验先验证速度，之后才进入专用声音训练；两者在历史中分别记录。同时加入中文数字读法处理，以及“最后结果可编辑，再点击朗读”的入口。

### 9. 让声音优化有可比较的实验过程

**2026-09-08–09，语音实验 v1–v7。** 在已有助手中接入过云端流式 TTS，增加声学参数分析、数据整理和训练辅助，再推进 CPU 本地声音微调。这里的流式播放是 TTS 音频到达后播放，不代表整条识别、语言模型和语音链路都已经流式化。

本地训练经历非有限梯度失败、稳定训练、扩大语料和不同推理步数比较。v4 形成快速 CPU 候选，v5 探索更自然的语气，v6 探索双语，v7 定向修复英文。选择依据包括实测和盲听；新候选没有自动替代旧候选，快速与高质量路线并存，界面增加 4/8/16 步控制。

历史本机最终选择中文 v6、英文 v7、8 步，并按语言分流。分句与播放器也一起改进：优先在完整标点处切分，连续复用播放器，减少提前截音和段间接缝，并完成长段中英交替试听。这些私人训练包只记录实现和选择过程，不随公开项目分发。

### 10. 解决多入口启动和音色列表反复失效

**2026-09-08–09，未另立应用版本号。** 多次更新后，界面恢复并不等于从桌面或任务栏重开也正常。开发中曾用内置/外置语音布局作对照，随后统一正式安装位置、修复按键监听器恢复、加入配置持久化与稳定音色 ID。

最终对重开故障的定位是：不同启动环境访问了不同的数据目录，文件本身并未消失。固定引导与数据路径后，完成真实桌面连续冷启动验证；历史记录没有声称完成整机重启验证。

### 11. 整理为他人可安装和扩展的公开项目

**2026-09-18，`repro-2026.09.18` 系列。** 将应用、研究工具、固定依赖和文档整理到同一项目，提供统一 GUI/CLI 入口和独立用户数据目录。基础规则功能无需私人配置即可启动。

本轮扩展了通用本地模型门户，支持 Ollama 与 OpenAI 兼容服务；增加模型发现、只读路由测试、操作契约导出和陌生模型接入 Skill。语音侧提供纯数据包格式、空模板、资源与模型加载校验，以及本地导入入口。源码发行包附文件清单与 SHA-256，并加入 Windows 自动验证。

首版公开后，`.1` 统一了通用项目文档与测试指南；`.2` 补齐制作动机、当前功能和本页的开发过程。它们属于公开源码与文档整理版本，没有把应用核心另行标成 `v0.24`。
