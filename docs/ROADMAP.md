# 发展方向与前景

[项目首页](../README.md) · [当前功能](PROJECT_OVERVIEW.md) · [亮点与同类方案](DIFFERENTIATION.md) · [版本历史](VERSION_HISTORY.md)

更新日期：2026-09-18。本页记录作者的产品目标、工程路线和商业设想；规划中的功能、成本目标及合作方向不作为当前已交付的能力。

## 愿景：给更多电脑装上自己的语音助手

KeyPilot 从“替代 Copilot 键，再做一个 Windows 版 Siri”出发，长期目标是让不同品牌、小厂整机和自配 Windows 电脑，都能以较低成本获得接近系统原生的助手体验：随手唤起、直接说出需求、操作电脑，并用自己选择的声音回复。

近期重点是把已有工程变成普通用户能够安装和持续使用的成熟 App。用户应当能够在应用里选择本地模型、API 模型和声音，而不必先学会搭建开发环境。基础操作保持免费使用；本地推理与本地合成降低持续服务费用，需要更强能力时再由用户选择云端服务。

“给每台电脑提供类似 Siri 的功能”是长期愿景。当前实现聚焦 Windows 的已注册操作；不同硬件、系统版本和模型能力仍需分别适配、验证。

## 现有基础与下一步目标

| 方向 | 当前已有基础 | 下一步要达到的体验 |
| --- | --- | --- |
| 安装与部署 | 固定依赖、安装脚本、统一启动、环境检查与源码发布包 | 安装 App 即可使用基础功能，无需手动配置 Python、命令行或运行环境 |
| 本地模型 | Ollama / OpenAI 兼容服务接入、模型发现、响应校验与只读探测 | 自动识别硬件，选择适合的模型，一键下载、校验、启动与切换 |
| API 模型 | 兼容 API 地址、密钥保存、连接测试与模型选择 | 在向导中选择服务商、完成必要授权，再选择模型；展示连接状态与费用来源 |
| 个性化声音 | 本地包规范、资源与加载校验、导入试听；已有多条语音实验路线 | 短样本录音向导、质量检查、可选制作方案和自动导入 |
| 持续使用 | 按需加载、预热、可中断朗读、配置持久化和历史修复 | 完整升级、回滚、恢复、卸载和错误诊断，跨机器使用不再依赖开发者协助 |

“零配置环境”指用户无需手动配置运行环境。模型文件仍需下载，麦克风仍需授权，使用付费 API 时仍需账户或密钥；应用负责把这些步骤做成清楚、可恢复的引导。

## 近期路线：先成为成熟 App

| 阶段 | 主要工作 | 完成标准 |
| --- | --- | --- |
| 1. 安装后就能完成基础操作 | 应用安装包、运行环境管理、首次启动向导；麦克风与按键选择；统一管理按键与计时后台、退出和卸载 | 在未安装开发环境的干净 Windows 电脑上，通过界面完成安装、启动、文字操作、计时任务与基础朗读；异常可诊断，卸载能区分程序和个人数据 |
| 2. 在应用里选模型 | 硬件与磁盘检查、经过验证的模型目录、下载进度与恢复、模型切换、API 服务向导 | 普通用户无需打开终端即可接入一款已支持的本地模型或 API 模型；下载、鉴权或加载失败时仍保留基础操作 |
| 3. 完成声音定制闭环 | 短样本采集、噪声和转写检查、本地 GPU 与云端辅助制作选项、训练进度、试听及包导入 | 从参考录音到可用声音均有明确状态；独立测试文本可正常发声，失败可重试且不覆盖已有可用音色 |
| 4. 验证日常使用质量 | 更新与回滚、不同硬件适配、长期运行和冷启动检查、有限范围的离线识别评估 | 记录安装成功率、操作成功率、首音等待、空闲资源和付费调用量；用真实使用反馈决定后续扩大范围 |

本地模型目录应优先提供少量经过验证的组合，并说明下载体积、硬件需求、操作契约通过情况和模型许可。兼容同一种 API 不代表所有模型都有相同的理解或执行质量。

近期先打通“安装 → 选择模型 → 完成常用操作”的路径，再把声音制作和硬件合作纳入稳定产品。具体发布时间以这些验证结果为依据。

## 声音方向：一次制作，本地长期使用

计划提供两条路径，让不同硬件条件的用户都能选择合适的方案。

### 本地 GPU 直接合成

显卡与显存满足所选模型要求时，使用本地语音模型和短参考音直接合成，减少对云端制作的依赖。参考音驱动的零样本克隆不一定需要为每位用户训练新权重；它与专门微调一个音色是两种不同流程。当前项目已有相关适配与实验记录，未来需要把兼容硬件检查、模型安装、试听和运行管理统一成 App 内的体验。

短参考音生成、CPU ONNX 推理与量化已有上游基础，可参考 [ZipVoice](https://github.com/k2-fsa/ZipVoice) 和 [sherpa-onnx 部署文档](https://k2-fsa.github.io/sherpa/onnx/tts/zipvoice.html)。这些能力来自相应上游，具体质量仍需对实际模型、录音和设备验证。

### 云端辅助制作，再部署到本地

面向没有足够本地算力、但希望获得定制声音的用户，探索可选的按次制作服务：

1. 用户提供自己的或取得许可的短参考音，完成录音质量和转写检查。
2. 在所选服务允许的用途内，使用云端高质量语音模型生成教师语料；必要时租用云端算力运行训练。
3. 用这些数据微调可部署的本地语音模型，保留独立验证和试听文本；后续如研究蒸馏，单独验证其方法与效果。
4. 选择通过质量检查的候选，导出兼容的本地推理资源，完成量化前后对照和首次合成检查。
5. 导入用户电脑，后续日常合成使用本地资源，不必为每次朗读继续购买云端合成额度。

这里迁移的是通过训练得到的本地模型能力，不能假设能够从云端厂商直接导出其私有模型参数。项目历史已探索过“云端教师语料 → ZipVoice 微调 → ONNX INT8 本机部署”；当前公开版本提供研究代码与过程说明，尚未形成锁定全部依赖、面向普通用户的一键制作服务。现状见 [语音研究工具](VOICE_LAB.md) 和 [语音迭代历史](VERSION_HISTORY.md)。

**作者提出的初步成本目标是约 3 美元/次音色制作。** 这是待实测的目标预算，不是已经核算的完整成本、云厂商报价或最终售价。评估时需固定语料规模和质量要求，分别记录云端合成、训练算力、失败重试、存储与交付成本；如果提供付费服务，定价还需覆盖实际维护与支持。可先验证小规模、可重复的制作流程，再决定收费方式。

质量至少需要验证两点：未参与训练的中英文文本能否清晰、稳定朗读，避免漏字、重复和发音错误；以及相同文本与响度条件下，用户盲听是否更偏好新音色。训练损失下降或导入成功，都不能单独代表声音达到交付标准，扩大教师语料也不保证完整继承教师模型的音质。

公开仓库继续只提供实现方法、规范和空模板，作者的语音包、私人录音和权重不上传。未来云端辅助制作涉及用户选择的参考材料，需在产品中明确处理位置、用途和删除方式，并提供纯本地路径；这项规划不启用或授权上传现有本地资源。

## 长期方向：面向不同品牌与自配电脑

目标用户包括没有满意预装助手的小厂整机用户、自配主机用户，以及希望自行选择模型、声音和服务提供方的人。项目希望把按键、输入、系统操作、问答与声音反馈连成稳定的日常体验，让用户不必因为更换电脑品牌而重新组织整套使用方式。

可以按硬件和需求提供不同组合：

- 基础电脑先使用规则操作、系统声音，以及适合其资源的小型本地模型。
- 有较强 GPU 的电脑选择更大的本地模型和本地语音合成。
- 需要特定能力的用户选择 API 模型，在产品内明确服务来源和费用；是否更快或更准确由任务评测决定。

硬件自动匹配、可替换模型和可移植声音包，应共同服务于低门槛体验。长期竞争力需要来自安装成功率、日常操作可靠性、声音体验、持续成本和维护质量。

### 如何判断这个方向的前景

官方资料表明，个人助手与本地推理已经是多个平台持续投入的方向：

| 已核对事实 | 对 KeyPilot 的启示 |
| --- | --- |
| Apple 将 Siri 与系统及应用体验整合；Apple Intelligence 同时使用设备端处理与 Private Cloud Compute，功能支持受设备、系统、语言和地区条件影响。[产品说明](https://www.apple.com/apple-intelligence/)、[支持条件](https://support.apple.com/en-us/121115) | 可以学习随手唤起和系统操作体验；不能将 Siri 全部描述为纯本地，也不能据此推断其他电脑完全没有助手 |
| 联想于 2025-02-25 公告在指定 AI PC 新品上通过天禧 AS 部署端侧 DeepSeek 模型；2025-07-26 的官方文章列出包括通义千问在内的可选择模型生态。[端侧部署公告](https://brand.lenovo.com.cn/brand/ppn03246.html)、[模型生态说明](https://brand.lenovo.com.cn/brand/ppn03405.html) | 厂商正在投入端云结合与统一入口；产品支持有具体机型与服务范围，不能推成所有联想电脑都具备同样能力 |
| 微软提供可下载的 Windows Copilot，同时推进能在多种硬件上运行的本地模型工具；Foundry Local 支持模型缓存后的离线推理和硬件适配。[Copilot 入口](https://www.microsoft.com/en/microsoft-copilot/for-individuals/get-copilot)、[Windows AI 官方 FAQ](https://learn.microsoft.com/en-us/windows/ai/faq) | 非特定品牌电脑已经存在 AI 选择。KeyPilot 的机会应落在低门槛、统一操作体验与个性化上，也可以评估复用成熟运行时 |

基于这些资料与当前项目能力，**本项目对前景的判断是：面向跨品牌 Windows 用户，仍值得验证低成本、易安装、可自选模型和声音的助手产品。** 这是一项产品方向判断，不是已证明的市场规模或成功预测。“小厂和自配电脑没有预装统一体验”可以作为待验证的用户需求，不能写成“这些电脑无法使用 AI”或“只有少数品牌能够运行本地 AI”。现有独立助手的对比见 [同类方案分析](DIFFERENTIATION.md)。

## 合作与商业化设想

厂商与模型提供方合作已有官方先例：联想于 2025-02-21 披露与 DeepSeek 在个人智能和企业智能领域合作；通义实验室负责人在 2023-12-07 的公开发言中提出与联想探索 AI PC 端云协同，该发言由联想官网于 12-24 发布。前者是明确的合作披露，后者是公开的合作方向表态，不据此推断独家关系或未公布的签约条件。[DeepSeek 合作披露](https://brand.lenovo.com.cn/brand/ppn03235.html)、[通义实验室发言](https://brand.lenovo.com.cn/brand/ppn02465.html)

在个人用户版本稳定后，可以探索与小型整机厂商、装机商或模型提供方合作：由合作方承担适配、模型部署或一定额度的服务成本，KeyPilot 提供统一的助手界面与操作接入。用户获得预先验证的组合，仍保留选择其他模型与声音的入口。

可讨论的合作内容包括预装与售后支持、符合分发许可的本地模型包，以及明确用量范围的 API 额度。厂商提供模型或补贴服务，不自动意味着用户永久免费无限使用；需要事先明确费用承担、更新维护和数据处理责任。正式分发前也需明确本项目与第三方组件、模型的许可，目前仓库尚未指定独立开源许可证，见 [第三方组件与分发范围](../THIRD_PARTY_NOTICES.md)。

以上均为未来设想。KeyPilot 当前没有宣布与文中提及的厂商或模型提供方建立合作。本阶段最有价值的验证，是让目标用户在自己的电脑独立安装并持续使用，再以实际留用情况、问题反馈和运行成本决定合作范围。
