# 版本与实验迭代历史

本页是依据历史任务、版本归档和实验报告整理的**技术迭代摘要**，不是原始聊天备份。语音包仅在作者本机使用；当前项目只分发实现代码、接口规范和空白配置模板，不上传声音包、录音、合成音频、训练数据、模型权重、凭据或私人授权材料。下文提及云端语音是历史路线记录，不表示本次分发会上传或附带任何声音资源。

项目存在三条不同编号线：`KeyPilot v0.x` 是历史应用版本，语音 `v1–v7` 是模型候选/实验编号，`repro-2026.09.18` 及其修订号是公开可复现项目的分发版本。训练步数 `400` 与推理步数 `4/8/16` 也不相同。以下按实际证据保留编号，不把实验目录或分发文件名虚构成 Git 标签；文档修订也不意味着应用升级到 `v0.24`。聊天时间按 UTC 归日；实验报告保留其原标注日期，跨时区可能相差一天。证据编号对应 [来源索引](HISTORY_SOURCES.md)。当前功能与使用场景见 [项目简介](PROJECT_OVERVIEW.md)。

## 起点：替代 Copilot 键，再做一个 Windows 版 Siri

最初的动机是**替代 Copilot 键原来的用途，然后做一个 Windows 版 Siri**。2026 年 9 月 2 日，作者电脑上的 Copilot 键通常打开搜索，现有设置无法满足想要的自定义方式。最初先用它打开指定应用或直接进入 GPT 语音；随后希望把这个入口发展成自己的 Windows 助手，用一句话完成打开应用、调整音量和亮度等日常操作。（H01；作者在公开项目整理时再次确认这一动机）

实际使用很快改变了设计重点。简单指令若每次都开启云端语音聊天，会产生过多会话记录；只靠固定关键词又理解不了自然说法。因此，9 月 3 日的设计逐步转向“常见操作要快、优先本地处理”：规则先处理明确命令，本地模型只从已注册 Skill 中选择操作并填参数，无法完成的复杂任务才按用户选择转接。由此形成了独立桌面界面、本地操作层与可选问答服务的分工。（H01）

后续迭代由使用中暴露的问题推动：找不到应用便加入桌面候选和自定义关键词；设置只能打开不能定位，便加入自动填写与回读；旧播报无法打断，便调整播放进程；本地知识回答不可靠，便拆分联网策略；自定义声音慢或不稳定，便比较克隆、变声、CPU 微调与不同调度方案。到 9 月 18 日，工作重点进一步转为让其他人能够安装、替换模型并根据规范接入自己的声音，而不依赖作者的电脑配置或私人资源。（H01–H03、H13）

## 关键纠错记录

- **明确区分模型与应用**：规则能够执行并不能证明 LLM 接通；模型返回合法 JSON 也不能证明实际执行成功。本次门户因此把 `not_executed` 写入探测结果。
- **明确区分训练与推理**：Qwen/ZipVoice 零样本参考音方案没有因此获得专用训练；RVC 权重不能装入 ZipVoice。CPU 原生微调从 v1–v4 才逐步形成独立路线。
- **不以新版本自动替代旧版**：v4-500 指标回退，没有替代 v4-400；v5 在 4 步下不稳，保留 v4；v6 英文客观指标改善但听感不佳，英文继续用 v5，直到 v7 定向修复。
- **区分恢复与根治**：音色改名、重启、恢复设置和目录缓存曾恢复界面，但 9 月 9 日才以真实启动进程的路径证据定位重定向。验证覆盖桌面连续冷启动，没有声称做过整机重启。
- **区分局部与端到端性能**：RVC 200 毫秒块转换、TTS 整句生成、音频首包、播放器首声与用户说完到回复是不同指标。历史数据不能混算，更不能直接保证另一台电脑上的速度。

## 历史指标可支持的结论

v4 报告的单句 CPU 4 步结果是约 1.57 秒生成 4.64 秒音频；v5 报告同类对照显示 8 步更自然但接近实时速度；v6 的盲听与部分相似度指标出现分歧。这些支持“同时测速度、清晰度和听感，并保留旧候选”的工程决策，不足以证明普遍最优。

v7 的目标英文句参与过训练，不能用该句的改善证明未见文本泛化。历史材料尚未构成多说话人、多随机种子、足量独立听众的完整研究验证。测试通过数量也随测试范围变化，只作为当时开发记录，不作为跨版本性能评分。复现实验方法见 [测试与复现指南](TESTING.md)。
