# 长期架构：从快捷键到本地语音助手

## 目标

让 Copilot 键成为统一入口，同时保持三个原则：本地优先、动作可审计、危险操作必须确认。

```text
Copilot 键 / 唤醒词
        ↓
本地录音 + VAD（只截取说话片段）
        ↓
本地语音识别（ASR）
        ↓
小型本地模型：只选择 skill 并填写 JSON 参数
        ↓
Schema 校验 → 权限策略 → 必要时确认
        ↓
确定性的 Windows 执行器
        ↓
状态提示 / 本地 TTS
```

核心设计不是让小模型“直接控制电脑”，而是让它在很小的候选集合中完成分类和填参。每个 skill 都包含：清晰描述、严格 JSON Schema、少量例子、风险等级、确认策略和固定执行器。这样对本地模型的推理能力要求低得多，也能防止一句识别错误的话直接删除文件或发送消息。

## 分层

### 1. 输入层

- 第一阶段：Copilot 键按住说话，松开结束。
- 第二阶段：可选的本地唤醒词；默认关闭持续监听。
- VAD 只把有效语音片段交给 ASR，降低 CPU 和延迟。

### 2. 理解层

- ASR 负责把语音转成文本。
- 小模型只返回 `{ "skill": "...", "arguments": {...} }`，禁止输出 shell 命令。
- 模型上下文只放当前可用 skill 的摘要；选中后再加载完整 schema 和例子。
- 当置信度低、参数缺失或多个 skill 冲突时，先追问，不执行。

### 3. Skill 注册表

每个 skill 独立存放并可按需加载。本项目在 `skills/` 中提供两个接口草案。

建议字段：

- `id` / `description`：帮助小模型选择工具
- `input_schema`：限定参数类型、范围和枚举
- `examples`：给弱模型少样本提示
- `risk`：`low`、`medium`、`high`
- `confirmation`：`never`、`when_ambiguous`、`always`
- `executor`：映射到经过审核的本地函数，不接受任意代码

### 4. 策略层

- 低风险：打开白名单应用、读音量、查时间，可直接执行。
- 中风险：改系统设置、关闭应用、移动文件，需要显示动作预览。
- 高风险：删除文件、安装程序、输入密码、转账、代表用户发送消息，必须逐次确认；部分能力应默认禁用。
- 所有动作记录本地审计日志，但不记录原始麦克风音频和敏感参数。

### 5. Windows 执行层

优先级建议：

1. 官方 API / URI / PowerShell cmdlet
2. UI Automation 可访问性树
3. 键盘快捷键
4. 坐标点击（最后手段，脆弱且风险高）

## 里程碑

### M0：硬件键 MVP（当前）

- 拦截 `Win + Shift + F23`
- 单击、双击、长按
- 打开 ChatGPT 与触发语音快捷键
- JSON 自定义动作

### M1：可用产品壳

- 托盘图标、图形设置页、按键学习模式
- 应用选择器与开机启动开关
- MSIX 打包和签名，使应用有机会出现在 Windows 原生选择列表
- 状态浮层：监听中 / 识别中 / 执行中 / 需要确认

### M2：本地语音与首批 skills

- 按住说话、本地 VAD、流式 ASR、本地 TTS
- `open_app`、`set_volume`、`search_files`、`window_control`
- 规则路由优先，小模型处理自然表达和参数抽取

### M3：受控桌面助手

- UI Automation 执行器
- 权限和确认中心
- skill 商店或本地 skill 目录
- 可选云模型回退；敏感内容默认不上传

### M4：Siri 式体验

- 可选唤醒词、连续对话、上下文窗口
- 多步计划，但每一步仍通过 skill 和策略层
- 设备端个性化、离线核心能力、可撤销动作

## 下一步技术选择

MVP 验证交互后，正式桌面端建议迁移到 C#/.NET：低级键盘钩子、Windows App SDK、UI Automation、MSIX 和系统托盘都更自然。Python 继续承担本地语音和模型服务，两者通过本机命名管道或 localhost 通信。这样 UI 不会被模型运行阻塞，也方便替换不同大小的本地模型。
