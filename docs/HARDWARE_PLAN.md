# 当前电脑的本地模型方案

检测到的硬件：

- CPU：AMD Ryzen 9 9955HX，16 核 / 32 线程
- 内存：31.2 GB
- GPU：NVIDIA GeForce RTX 5070 Ti Laptop GPU
- 显存：12,227 MiB

这台电脑并不是“本地模型算力很弱”的档位。只要把模型职责限制为 skill 选择和参数填写，完全可以获得很低的本地延迟，同时给语音识别和桌面程序留出显存。

## 推荐起点

### 语音识别

- 运行时：`whisper.cpp`，启用 CUDA。
- 起步模型：多语言 `small`；中文准确率不够时升级到 `medium`。
- 配合 VAD，只处理按键期间的有效语音，不做全天候录音。
- 先做“按住 Copilot 键说话”，稳定后再考虑唤醒词。

### Skill 路由模型（已启用）

- 模型：Ollama `qwen3:8b`，当前下载体积约 5.2 GB。
- 运行时：Ollama 本机 API；实测在 RTX 5070 Ti Laptop GPU 上为 100% GPU 推理。
- 使用非思考模式，输出受 JSON Schema 约束的 skill 调用。
- 每次只给模型 5–15 个候选 skill 的摘要，不把整个 skill 库塞入上下文。

8B 模型的职责只包括：

1. 判断用户要调用哪个 skill。
2. 从话语中抽取受限参数。
3. 参数不完整时生成一句澄清问题。

它不直接写 PowerShell、不生成鼠标坐标、不绕过确认策略。复杂问答仍可交给 ChatGPT；本地模型负责速度、隐私和离线控制。

## 显存安排（目标值）

```text
Skill 路由模型（8B 量化）     约 6 GB
语音识别模型                 约 1–3 GB
KV cache / CUDA 工作区        约 1–2 GB
桌面与其他程序预留            至少 2 GB
```

暂不需要升级到 14B 或更大的模型。对有限、类型化的 skill 路由，提升 schema、例子和确认策略通常比单纯增大模型更有效。

## 建议验收指标

- 按键到开始录音：小于 100 ms
- 松键到中文转写完成：短句小于 700 ms
- skill 选择和 JSON 参数：小于 300 ms
- 常用指令端到端：目标 1 秒左右
- 50 条个人常用中文指令的 skill 选择准确率：至少 98%
- 危险动作误执行：0；不确定时必须追问
